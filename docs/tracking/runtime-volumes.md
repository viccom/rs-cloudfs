- 2026-09-11：**RV1 落地**（feat/runtime-volumes）——注册表动态化 + WebDAV/仪表盘动态分发（TDD：编译红×3 → webdav 10/10、web 14/14+30/30、cli 14/14；workspace 925/0/12、winfsp 117/0/1 全门禁绿）。spike 结论（读 dav-server 0.11.0 源码钉死）：dav-server 的分发本就 per-request（`service_fn` 每请求一跑，keep-alive 测试已证）；`DavHandler` = `#[derive(Clone)] { config: Arc<DavConfig> }`，FakeLs 是 `DavConfig.ls: Box<dyn DavLockSystem>` 藏在 Arc 内——克隆共享同一锁态（现生产代码每请求克隆整个 handler 表、真机 Explorer LOCK→PUT 链已验证），故动态形态 = 静态 `HashMap` 换 `Arc<RwLock<有序表>>`，handler 在 insert 时构建、remove 时随条目销毁，锁不跨 await（查表+克隆后放锁）。分层裁决：三 crate 各定义自有面 `RegistryHandle`（条目携带 L5 自有类型——webdav 的 DavHandler / web 的 WebUiConfig / cli 的 VolumeRuntime；core 承载即向上依赖违反 R1），cli 主表为 master 真源、两面表为投影，RV2 串行 mutator 统一变更。serve_volumes 统一为动态模式（不保留静态形态——避免死 API；既有测试仅 serve_two/multi_server 两个 helper 机械适配，断言零漂移）。用户面文档（README 运行态卷管理）随 RV3 收口。
