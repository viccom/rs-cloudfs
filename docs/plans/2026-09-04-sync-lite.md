# cydrive-sync 轻量云端元数据同步（家庭版）设计 + 实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**定位（负责人 2026-09-04 指令）**：家庭成员少量用户；rust + sqlite；轻量简化；成员间数据安全非重点。

**Goal:** 一个小服务端 crate（axum + rusqlite）+ cydrive 客户端同步模块：多实例/换机共享同一份盘索引，LWW 最终一致。

**Architecture:** namespace 键 = `hex(SHA-256(bot_token + ":" + chat_id))`（服务器永不存裸 token；同 bot+chat = 同盘，不同成员各自 bot = 各自盘，两种拓扑同一机制）。逻辑行 = files 行 + 其 chunks 序列化进 JSON payload（绕开 file_id 重映射）。每 namespace 服务端单调版本计数器做 LWW；删除 = 墓碑行。本地新增 `sync_mirror`/`sync_state` 两张附加表（不碰 Python 契约表）。

**Tech Stack:** 既有栈零新依赖（axum 0.8 / rusqlite bundled / serde_json / sha2——sha2 已在 core crypto 用过则复用，没有则加（RustCrypto，许可清洁））。

## 服务端（crate `cydrive-sync`，bin `cydrive-sync-server`）

- SQLite 表：
  - `namespaces(key TEXT PRIMARY KEY, version INTEGER NOT NULL DEFAULT 0)`
  - `rows(ns_key TEXT, rel_path TEXT, version INTEGER, deleted INTEGER NOT NULL DEFAULT 0, payload TEXT NOT NULL, PRIMARY KEY(ns_key, rel_path))`（payload 为空串表示墓碑）
- 端点（全部 POST + JSON）：
  - `POST /v1/push` `{key, secret?, rows:[{rel_path, deleted, payload}]}`：可选 secret 与服务端配置比对（防陌生人，家庭级）；namespace 不存在则**自动注册**；对每行 `version = ++counter` 并 upsert；返回 `{max_version}`。
  - `POST /v1/pull` `{key, since}`：返回 `{rows:[{rel_path, version, deleted, payload}], max_version}`。
- 配置：env `SYNC_LISTEN`（默认 127.0.0.1:8290）、`SYNC_DB`（路径）、`SYNC_SECRET`（可选）。TLS 交给反代（caddy/nginx），不内建。
- 部署形态：单二进制 + 一个 db 文件 + 一行 systemd unit（复用 deploy/ 模式）。

## 客户端（cydrive-cli + core 增量）

- config 新键：`sync_url`（Option，None=功能关）、`sync_interval_secs`（默认 300，1..=86400）；KNOWN_TOML_KEYS 追加、legacy json 拒收、validate 校验。
- 本地附加表（MetaDatabase 新方法，schema 纯增量）：
  - `sync_mirror(rel_path TEXT PRIMARY KEY, row_hash TEXT, server_version INTEGER NOT NULL DEFAULT 0)`
  - `sync_state(id INTEGER PRIMARY KEY CHECK(id=0), max_pulled INTEGER NOT NULL DEFAULT 0)`
- 逻辑行序列化（core 新纯函数）：files 行 + chunks[(index,msg_id,size)] → payload JSON；row_hash = SHA-256(payload)。
- 同步算法（core 纯内核 + cli IO 壳，全测）：
  1. `pull(since=max_pulled)` → 对每行：墓碑→删本地 files/chunks 行+mirror；version > mirror.server_version 且本地 hash ≠ payload hash → 覆盖本地（remote wins）；本地无 → 插入（含 chunks 重建）。
  2. diff：本地每行 hash vs mirror（新增/变更）→ push 列表；mirror 有而本地无 → 墓碑。
  3. `push` → 更新 mirror.server_version 与 max_pulled。
- 触发：`cydrive sync` 手动子命令（connect_stack 不需要——同步不碰传输！只 db+http）；run 内启动一次 + 周期任务（失败 warn 不影响服务）。
- 冲突语义（家庭简化，记 decisions）：后推者胜（LWW by server version）；双机同路径并发上传→一方行胜、另一方远端消息成孤儿（无害，现状即如此）；双机收同一入站消息→payload 相同幂等收敛；加密行 payload 含 is_encrypted 原样同步。

## 任务（TDD，两批）

- **Batch A（服务端）**：crate 骨架 + 协议类型 + push/pull 语义（纯逻辑经内存 db 测：注册/版本递增/LWW/墓碑/since 增量）+ axum 端点 e2e（tokio TcpListener 拉起真服务）+ bin。~450 行。
- **Batch B（客户端）**：config 两键红绿 → MetaDatabase sync 表方法红绿 → 逻辑行序列化/diff/pull-apply 纯内核红绿（双实例模拟：两个临时 db 经同一 server 收敛）→ `cydrive sync` 子命令 + run 周期接线 + e2e（本地起 server，两 db 同步一致）。~700 行。
- 真机验收：本机/WSL 起 server，Windows 实例与 WSL 实例互同步（用户 WSL 空盘场景正是验收用例：sync 后两边列表一致）。生产部署到负责人服务器（人工步骤，给 unit 文件）。

## 不做（v1）

用户/权限/配额、内建 TLS、冲突 UI、实时推送（轮询周期足够）、按行拉取去重优化（家庭规模不需要）、sync 与上传队列的事务耦合（sync 传播 pending 行无害——对端看到 is_uploaded=0 且无本地副本 = 幽灵行，pull 端跳过无本地副本的 pending 行即可，已列入内核语义）。

## 规模与风险

总量 ~1100–1400 行（测试约四成）；破坏面≈0（新 crate/新表/新键全增量，热路径零触碰）；最大风险 = pull-apply 与本地并发写的竞态（缓解：MetaDatabase 已内部 Mutex 化，apply 走既有 upsert/delete 方法）。
