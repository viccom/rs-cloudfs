## 1. 路线裁决（123-0 的核心产出）

### 1.1 路线 B：web API（**推荐主路线**——pan123-rs 实证 Rust 可行）

- **域名**：`api.123278.com`（**动态域名发现** `/api/dydomain` 防封轮换——客户端启动时解析，失败回退默认）+ `login.123pan.com`。
- **认证**：QR 三端点（`/api/user/qr-code/{generate,result,wx_code}`，123 App/微信扫码）或密码 `sign_in` → token；请求**双头**：`Authorization: Bearer {token}` + `Cookie: sso-token={token}`；`Origin/Referer: https://yun.123pan.cn` 必带。
- **签名**：pan123-rs 实测形态 = `dynamic_params()`（**随机 i32 key** + `timestamp-rand-rand` 值）——**无** PCFS 的 CRC32 替换表计算。两实现并存说明服务端对 key 的校验已放松；我们按 pan123-rs 形态起步，PCFS sign.go 作为回退实现（若 spike 实测拒签）。
- **上传**：`upload_request`（MD5 etag + type 0/1 + duplicate 模式）→ 服务端下发 `slice_size`（**123-0 实证 "16777216"=16MiB 字符串形态**；客户端可自定 ≥5MiB）→ 逐分片 `s3_repare_upload_parts_batch` 换 **presigned URL** → `PUT` 直传 OSS → `upload_complete/v2` 全量 body（**isMultipart:true 恒真——123-0 完成态矩阵**）。**无 OSS 签名自研**（presigned 是服务端签的）。
- **下载**：`/b/api/v2/file/{download_info,batch_download_info}` → URL；**CDN 尊重 Range**（pan123-rs 续传实证：`bytes=N-` → 206/Content-Range 解析）；**`/b/api/file/download/traffic/check` 每日流量限额**（123 非会员限制——README 明示不破解、会员 9 元/月解除）。
- **文件操作**：`list/new`、`info`、`mod_pid`（移动）、`rename`、`trash`（**`event: "intoRecycle"` 删除进回收站**）、copy async（任务轮询）。
- **风险**：web 私有接口（猫鼠风险中等——作者自觉「支持官方、不破解限制」的合规姿态 + 动态域名设计说明被针对过）；**每日下载流量限额是产品级约束**（负责人若为非会员账户，挂载卷的下载量会触顶）。

### 1.2 路线 A：官方开放平台（备选）

open.123pan.cn：client_id/client_secret → access/refresh token；**下载/预览需「直链空间」**（目标文件夹手动开启 + 可能需 VIP），根目录无直链；上传支持秒传/分片。免审秒发凭证（2026 社区确认），但**直链门槛对「挂载卷 + 流式播放」这个核心场景是硬伤**——若负责人无 VIP 或不愿开直链空间，路线 A 的下载面残缺。

### 1.3 裁决规则（**已被负责人 2026-09-14 直裁关闭——D1 = web API，K64**）

原设计为「123-0 双腿并测后三选一」；负责人已直接拍板走 **路线 B（web API）**。路线 A（开放平台）降为纯文字参照（不再 spike）；123-0 的职责随之收窄为 **web API 的验证与采样**（登录/动态域名/Range/流量限额数字/upload 全链/分片状态保留/密文空 etag）。

## 5. 硬纪律（两仓库实战坑 + 本轮新发现）

1. **blocking → async 全量转换**：pan123-sdk 是 `reqwest::blocking`（+内部线程池并发分片）——移植进我们的 tokio 栈时改为 async + `tokio::spawn` 并发分片（或先串行起步，并行留优化）。**这是移植工作量主项**。
2. **动态域名发现**：启动时 `/api/dydomain` 解析实际 API 域，失败回退 `api.123278.com`；不硬编码单一域名（防封轮换设计）。
3. **双认证头**：`Authorization: Bearer` + `Cookie: sso-token=` 同发（pan123-rs 形态）；`Origin/Referer: yun.123pan.cn` 必带。
4. **5060 已存在码 + duplicate 真值（123-0 ⑤ 钉死）**：bare 请求撞名 → `code=5060` + `data{etag,size,updated_at}`；**`duplicate=2` = 真覆盖**——同名**同 FileId 原地**换 etag/size/UpdateAt（CreateAt 不变、无副本、不进回收站、/v2 完成响应直接回同 FileId）；`duplicate=1` = 保留两者（新条目 `name(1).ext` 自动改名）——**绝不漏到挂载面**。注意 **Reuse 优先于 5060**：内容（etag+size）已在服务端时 upload_request 不冲突直接秒传入库。
5. **MD5 前置 vs 流式（123-0 ⑥ 钉死）**：etag 缺省/空串均 `400 请输入Etag`——**必填无豁免**，队列暂存件预计算（明文卷+密文卷同理，一遍哈希 IO 代价照付）；且错 etag 无服务端内容校验（存储=声称值）——**必须算真 MD5**，否则假 etag 未来命中秒传会取回错误内容。
6. **大分片超时自适应**：PUT 超时 = `max(300s, chunk_mb × 2s)`（pan123-rs 实测值，照抄）。
7. **流量限额前置检查**：下载前 `traffic/check`，超额给明确 `RateLimited` 错误（人话指引会员/次日），不撞 403 迷雾。
8. **上传后 size 校验 + 分片幂等重试**（指数退避 + jitter——其 transfer.rs 形态）。
9. **IPv4 dial**：PCFS 同款（123 同样被观测到 v6 不稳；pan123-rs 未显式处理——我们照 baidu 形态加）。
10. **envelope 线事实三则**（123panNextGen 实证，R2 原料）：①**双成功码**——`code==0` 通用，`code==200` 仅 sign_in 与 QR 确认；②**字段大小写双拼解析**——`FileId/fileId`、`taskID/taskId`、`RedirectUrl/redirect_url`、`Code/Message/Data` 全双形态（serde alias/自定义反序列化）；③非 JSON 响应（HTML 错误页/空体）按解析失败归 `Unavailable`/`Io`，serde 不得崩穿。
11. **trash 静默失败陷阱（数据完整性级）**：payload 必须恰为 `fileTrashInfoList:[{"FileId":<int>}]`——形状错时服务端 **`code=0` 但实际不删**（123panNextGen `92ffe8c` 真机实测修复，2026-08-12）。推论：**逐端点照抄键名大小写**（trash 大写 `FileId`、delete 小写 `fileId`、mod_pid 大写 `FileId`、share 逗号串）——勿统一建模；**delete 后回读校验**。
12. **传输会话与 API 会话分离**：CDN GET 与 S3 presigned PUT 走**无 123pan 鉴权头的独立 reqwest Client**（123panNextGen 双 Session 形态先例；pan115 OSS K75-3 同源教训——伪装/鉴权头对 presigned PUT 多余且可能干扰）。
13. **上传严格序（123panNextGen 七步实证 + 123-0 完成态矩阵修正）**：upload_request（`Reuse=true` 即秒传命中，零流量）→ `s3_list_upload_parts`（续传差集）→ 批量预签名 `s3_repare_upload_parts_batch`（**官方拼写错误 "repare" 勿「纠正」**；参数 `StorageNode` 大写，与 list/complete 的 `storageNode` 小写不一致——逐字照抄）→ 逐分片纯 PUT（无表单无鉴权头）→ 再 list 确认 → `s3_complete_multipart_upload` → **`upload_complete/v2` 全量 body（UPPERCASE `StorageNode` + `isMultipart:true` 恒真——presign 走 repare 即 multipart 会话，**新单键 `{fileId}` 形态 / `isMultipart:false` 对该会话 code=0 静默不入库**；漏掉 complete 全家 = 文件不入库）；/v2 回 `data.file_info`（snake_case）= 真实 FileId+真 MD5；>64MB 在 complete 后 sleep 3s 再确认。**分片尺寸：服务端 `SliceSize`="16777216"（16MiB，字符串）为上界参考，客户端可自定 ≥5MiB（OSS multipart 最小片）——起步按 5MiB 固定值（123panNextGen 形态），大文件分片尺寸实现期定**。续传 = S3 会话五元组（bucket/storage_node/upload_key/upload_id/up_file_id）持久化 + mtime(±1s)/size 校验 + list_parts 跳已传分片——**123-0 ⑤ 已实证服务端保留会话：同参重发 upload_request 返回同一 UploadId+up_file_id**（本地五元组丢失亦可恢复）；resume 能力位判据已满足（断言⑦后点亮）。
14. **dlink 一次性纪律**：下载 URL 可能限次/短时效——**禁止重复 GET 探测**，缓存复用（baidu dlink TTL 同款）；CDN 可能回 **JSON 重定向体**（Content-Type:json + `{"code":0,"data":{"redirect_url":...}}`，最深跟 3 跳）——reader 流须检测该形态（真机才测得出的怪癖，桩要预埋）。
15. **重试/退避实测常量**（123panNextGen CDN 值，可采）：HTTP 429/5xx 优先 `Retry-After` 头（clamp 1–60s），否则指数退避封顶 30s + 抖动；限流重试上限 6、普通错误 3——与 K62.3 令牌桶限速并存。
16. **时间字段双态解析**：`CreateAt/UpdateAt` = int Unix 秒或 ISO8601 字符串双形态（Entry mtime 真源，serde 双态反序列化）。
17. **域名粘性 fallback**：主域 ConnectionError → 会话级**永久**切备域（不反复振荡）；主备以 spike 实测为准（§3.1）。
