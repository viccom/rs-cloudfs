# Phase 5 计划：115 网盘存储驱动（pan115）

> 状态：**方案待负责人批准**（2026-09-14 立）｜ 批次编号 115-0 … 115-5
> 前置研究：双仓库只读勘察（2026-09-14）——`E:\Go_codes\PrivateCloudFS`（Go，私有 web API 路线）+ `E:\GitHub\115-plus-desktop`（Rust+Tauri，官方开放平台路线，MIT，活跃至 2026-08-19）；情报见附录 A
> 前置依赖：**Phase 4（SFTP）SF1 的 `compiled_drivers()` 可扩展化重构**——第 4 驱动把 3 位元组穷举改成可扩展形态后，第 5 驱动只是加一个臂。若两阶段执行顺序对调，该重构的所有权随之对调（只做一次）
> 上游标准：`docs/standards/architecture.md`（R1–R7）、`docs/standards/driver-onboarding.md` §1–§9（**全量公民路线**——115 有按路径枚举面）、`docs/standards/interfaces.md`（契约/八断言）
> 需求口径：自用项目（K59.1）；「能跑起来、坑最少」唯一标准；门禁纪律照旧

## 0. 一句话方案

新增 L1 驱动 crate `crates/drivers/ck-pan115`（feature / backend 键 / 配置前缀统一 **`pan115`**——crate 名不可数字开头，且与 PCFS `drivers/pan115` 命名对齐），实现 `StorageDriver` + `CloudTransport` 双面（照 `ck-baidu` 的 api/oauth/driver/transport-face 结构）；协议层**主路线走官方开放平台**（`proapi.115.com`，115-plus-desktop 实证 Rust 可行），**PCFS 私有 web API 为保底路线**；OSS 分片上传直接用 `ali-oss-rs` crate 不自研；组合根接入第 5 个 feature；**L2 以上零改动**，现有驱动零侵入。

## 1. 路线裁决（115-0 的核心产出——本计划与 SFTP 的最大不同）

### 1.1 路线 A：官方开放平台（推荐主路线）

- **认证**：AppID/AppKey + **device-code 扫码流**（`passportapi.115.com/open/authDeviceCode` → `qrcodeapi.115.com` 扫码 → `deviceCodeToToken` → access/refresh token；`/open/refreshToken` 刷新）——**与 ck-baidu `oauth.rs` 同形态**，K13 TokenStore/凭据回写设施直接复用。
- **端点面**（115-plus-desktop `src/api/*.ts` 全白盒，附录 A.2 全表）：`/open/ufile/files|copy|move|update|delete|downurl`、`/open/folder/get_info|add`、回收站族、`/open/upload/init|get_token|resume`、`/open/user/info`、离线下载族与视频族（后者 v1 不做）。
- **依据**：官方文档背书、无签名逆向；115-plus-desktop 以纯 Rust 传输引擎在此路线上活跃开发（最近提交 2026-08-19，恰为 OSS 断点续传修复）。
- **前提（胜负手）**：**凭证可得性**。2026-08-09 有"115 API 开放平台暂停服务"报道（配套"违规使用专项治理"）；115-plus-desktop README 写"没有 115 开放平台的可加入 QQ 群获取"（群 978180785）——暗示**新申请通道已收紧**，存量应用仍可用（该仓库持续更新为证）。

### 1.2 路线 B：PCFS 私有 web API（保底）

- cookie 认证（UID/CID/SEID/KID）+ `LoginCheck`；`sign.go` 签名（CST 时间 12 位 → 数字替换表 → CRC32 双段）；两段下载（取链 + `Referer: https://www.115pan.com/` 解析——注意 PCFS 此处为 123 的形态，115 的对应约束见其 client.go：**CDN 校验取链时的完整请求头，必须原样回传**）；双路上传（≤10MiB `RapidUploadOrByOSS` / >10MiB 分片）；QR 三端点登录。
- **参照物**：PCFS `drivers/pan115/`（client.go 240 行圈定最小面）+ `SheltonZhu/115driver`（MIT，当前 main——**含 PCFS 锁定的 v1.2.3 之后的新教训**：CDN 下载链接绑定取链 UA、部分场景要求空 UA，issue #80）。
- **风险**：回到猫鼠游戏（115"安全威胁"式封禁先例，alist#7384）+ 密码/cookie 型凭据敏感度更高。
- **启用条件**：仅当路线 A 凭证不可得时，由负责人拍板是否接受风控启用。

### 1.3 裁决规则（写死，防悬空）

115-0 spike 输出三选一结论：① 拿到凭证 + downurl/Range/QPS 实测过 → **路线 A go**；② 凭证不可得 → 向负责人呈风控取舍，批准则路线 B go；③ 凭证不可得且风控不接受 → 本阶段挂起销账，结论入 decisions。

## 3. 端点 → 契约映射（路线 A；StorageDriver 九方法）

| 方法 | 端点/机制 | 备注 |
|---|---|---|
| `list` | `/open/ufile/files`（limit/offset 分页 → `Page`/`Listing::next`） | 字典序稳定排序驱动内自理（照 local 先例） |
| `stat` | `/open/folder/get_info` + list 兜底 | EntryId 句柄 = file_id（**稳定后端句柄**，onboarding §9） |
| `mkdir` | `/open/folder/add`（隐式父目录逐级建） | 已存在语义预检（百度 mkdir 教训同源） |
| `delete` | `/open/ufile/delete` | **语义拍板 D2**：回收站 vs 永久（另有回收站端点族可配套） |
| `rename` | 文件 `/open/ufile/update`；目录 = move 自身（spike 确认形态） | 预检目标存在 → Exists |
| `reader(range)` | `/open/ufile/downurl` → CDN GET + `Range` | **UA 绑定：请求必须带浏览器形态 UA**（115-plus-desktop 以 `navigator.userAgent` 调用）；先 HEAD 探测 Accept-Ranges/ETag（其 Rust 引擎先例）；CDN 429 → 分段级重试 |
| `writer(stager)` | `/open/upload/init`（SHA1+pre_sha1+preid+sign_key/sign_val 二次认证）→ `/open/upload/get_token`（OSS 凭证/端点）→ **ali-oss-rs 分片**（min 5MiB，自适应 max_parts）→ complete(callback) | commit-on-close：init 成功 ≠ 可见，complete 后对象才存在（天然契合 stager 契约） |
| `quota` | `/open/user/info` 的空间字段 | 字段名 spike 确认；缺失 → `total: None` |
| 秒传（可选 trait） | init 响应判存在 | `RapidUpload` + `WriteHint` 消费；**密文永不命中**（无害，位按后端原语声明） |
| `resume` | `/open/upload/resume` + OSS ListParts | **断言⑦驱动层可观测**（重传同路径只补缺失分片）；conformance 过⑦后才点亮该位 |

**错误映射表（R2，mock 回放钉死）**：开放平台 errno 形态在 115-0 spike 采集真机错误码后成表（照 `ck-baidu/tests/errno_mapping.rs` 先例）；CDN 429 → `RateLimited`/`Unavailable`；token 失效 → `Unauthorized{recoverable:true}`（刷新重放一次，照百度 110 先例）。

## 4. 架构与装配

### 4.1 能力位（R4 逐位依据）

`range_read: true`（HEAD 探测 + 分段实证）｜`multipart: true`（OSS 分片）｜`server_side_move: true`（move API）｜`rapid_upload: true`（SHA1+preid）｜`authoritative_index: true`（list 即真相 → rebuild 可用）｜`remote_delete: true`（delete API；产品语义随 D2）｜`resume: true`（**conformance 断言⑦验证后点亮**）｜`change_feed/inbound/chat: false`。

### 4.2 装配（12 处，与 SFTP 计划 §3 同清单）

差异项：① 第 5 个 feature `pan115`（`PAN115_DRIVER_REQUIRED` 文案照三件套形态）；② `compiled_drivers()` 在 SF1 重构后**仅加臂**；③ web 卷表单第 5 个 backend 选项 + 凭据组（app_id/app_key/或 cookie——随路线）；④ `build_driver`（rebuild）加臂，**受 QPS 约束需限速**（见 §7）；⑤ doctor/setup 分支（setup 引导扫码 = web 面板 QR 三端点，照 baidu OAuth 引导位）。

### 4.3 配置与身份

- 键：`pan115_app_id` / `pan115_app_key` / `pan115_access_token` / `pan115_refresh_token` / `pan115_root`（folder id，缺省 `"0"`；**D3 拍板**是否要求专用子目录）；路线 B 备用键 `pan115_cookie`。
- `SECRET_VALUED_KEYS` 增 `pan115_app_key`/`pan115_access_token`/`pan115_refresh_token`（照 `baidu_app_key` 先例，K58-M2）。
- VolumeId = `pan115:<uid>`；sync_namespace 同 baidu 形态（uid 摘要）。
- 卷模式 K19 三清单同步、K28 env 忽略规则照旧。

## 5. 硬纪律（两仓库实战坑，逐条入实现）

1. **downurl 的 UA 绑定**：开放平台取链请求必须带浏览器形态 UA（115-plus-desktop 用 `navigator.userAgent`）；web 路线则须回传取链时的完整请求头（PCFS client.go 注释明示）。
2. **CDN 429 分段级处理**：按分段计重试数 + 超限"重生"该分段（respawn 模式，115-plus-desktop commit 66d45a4 与 `handle_cdn_rate_limit`/`respawn_cdn_segment`）。
3. **OSS 续传双坑**：`PartAlreadyExist` 死循环（#29）与 **UploadId 意外重置**（#30）——两修法均为 2026-08-19 最新提交，照抄其判定逻辑。
4. **秒传哈希前置 vs 流式**：init 载荷需要 SHA1/pre_sha1——明文卷可由队列暂存件预计算；加密卷密文永不命中，spike 确认**能否省略哈希直传**（省一遍哈希 IO）。
5. **awaited close + 上传后 size 校验**：OSS complete 确认后核对远端 size 与本地一致（aeroftp/SFTP 计划 §4.4 同款纪律）。
6. **IPv4 dial**：PCFS 两驱动同款坑，复用 ck-baidu 的 reqwest IPv4 形态。
